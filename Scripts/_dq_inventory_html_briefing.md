## Class D — Method limitations and tooling defects

**D1. The unquoted-heredoc bug silently deletes the `$` and the following digit from every dollar figure**
Class D. `cat >> page.html <<EOF` makes bash expand `$688` as a variable, so **`$688,426.17` lands on the page as `88,426.17`**, `$36,313,407.97` as `6,313,407.97`, and `$196,001.10` as `96,001.10` (§17a). One agent corrupted **six of ten** page chunks this way, and on a budget page that is a page full of wrong money with nothing visibly broken. **It was caught only because `verify_quotes.py` failed the quotations containing amounts** — the quoted spans no longer matched the dialogue CSV. The fix: always write `<<'EOF'`, never `<<EOF`; if the page needs a shell variable, write the literal text and substitute afterwards with python.
Source: `verify_quotes.py` failing the quotations that contained amounts.
**Systemic** (six of ten chunks in one run; a hazard on every heredoc-built page).

**D2. `verify_quotes.py` mis-pairs quotation marks around spans under 8 characters, manufacturing phantom findings**
Class D. Its scanner is `"([^"]{8,600})"`, so anything **under 8 characters** inside typographic quotes is skipped — which shifts the open/close pairing for the rest of that block and manufactures REVIEW lines built out of the page's own prose. **Twelve phantoms on one page** (§17c). §22b then records that §17c was **under-stated**: the rule is not limited to single-token transcript items (`Yes.`, `Aye.`, `SAU`, `RSA`) — a quoted name (`"Chris"`, `"Whitney"`) or any single quoted word in the project's own prose does it too. **Never put fewer than 8 characters inside typographic quotes anywhere on a page**; use `<em>` instead, every time, and say so in the method footer. This is the second documented limitation of the checker; both are recorded in `pending_legal_anchors.md`.
Source: the checker's own regex `"([^"]{8,600})"`, and the twelve phantom REVIEW lines it produced on one page.
**Systemic** (a standing property of the tool).

**D3. `verify_quotes.py` used to truncate its findings list at 12**
Class D. It capped the list and printed "... and N more", which made a before/after audit of an edit impossible (§22a). Patched 2026-08-29: a single-page run now prints every miss, while `--corpus` still caps at 12 so the sweep stays readable. The whole list must be read.
Source: the tool's own pre-patch output behaviour.
**One-off** (fixed by patch).

**D4. `validate_pages.py` flags UTC clock times as malformed timestamps**
Class D. Writing a UTC clock time such as `14:06:36` trips `validate_pages.py`'s H:MM:SS note (§25c). The workaround is to drop the seconds when citing Drive metadata.
Source: `validate_pages.py`'s H:MM:SS note.
**Systemic** (a standing false positive), with a simple workaround.

**D5. Google Drive `search_files` under-reports, and no negative derived from it is safe — at least nine documented failures**
